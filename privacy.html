Privacy Policy

Effective date: 2026-10-07

This policy covers VantaGe Publisher (the "Tool"), the internal tool of the VantaGe brand, and this website. It says what data the Tool accesses, what it stores, how it uses that data, and how access can be revoked.

1. The Tool uses YouTube API Services

The Tool uses YouTube API Services (the YouTube Data API and the YouTube Analytics API). Data obtained through them is also subject to the Google Privacy Policy (http://www.google.com/policies/privacy). Use of the Tool is subject to the YouTube Terms of Service - see our Terms of Service.

2. Who uses the Tool

The Tool is not offered to the public. Its only user is the owner of the VantaGe brand, who signs in with Google using the account that owns the brand's YouTube channels. The Tool has no user accounts, no sign-up and no other users, and it does not access any other person's YouTube account or data.

3. What the Tool accesses

On sign-in the owner grants the Tool these Google OAuth scopes, and the Tool uses each only for the purpose listed:

ScopeWhat the Tool does with it
https://www.googleapis.com/auth/youtube.upload Uploads one of the brand's own finished videos to the brand's channel (videos.insert), together with the title, description, tags, category, language and audience settings the owner prepared. Every video is uploaded as private with a scheduled publication time, and only after the owner has confirmed that specific upload in the terminal.
https://www.googleapis.com/auth/youtube.readonly Reads the ID of the channel the signed-in account speaks for (channels.list with mine=true), to check before an upload that the video goes to the intended channel; and, at most once every 7 days, the status of the videos the Tool itself uploaded (videos.list, part=status), to keep the upload journal up to date (section 7). Nothing else is read with this scope.
https://www.googleapis.com/auth/yt-analytics.readonly Reads YouTube Analytics reports (reports.query) for the brand's own uploaded videos, per video and per day: views, engaged views, average view duration, average view percentage, likes and subscribers gained.

4. What the Tool stores, and where

Everything the Tool stores is kept on the owner's own computer, in the owner's project folder or (for the sign-in token) in a folder outside it:

  • Sign-in token. The OAuth token Google issues is saved in a file outside the project folder that only the owner's computer account can read. Next to it the Tool keeps a small status file with the time access was granted, the time the token is expected to expire (when Google gives it a fixed term), whether the app was in testing or in production at the time, and the scopes granted - not the token itself.
  • Upload journal. For each video uploaded, one record: the YouTube video ID and link, the scheduled publication time and privacy status as YouTube returned them, the title the owner wrote, the upload time, and the owner's own internal references to the video (its project file, its review record, the owner's confirmation). Videos the owner publishes by hand in YouTube Studio are entered into the same journal by the owner, with the video ID and time read in YouTube Studio; those records do not come from YouTube API Services.
  • Analytics metrics. For each of the brand's videos, one record per day with the metrics listed in section 3, a log of each collection run (when it ran, which videos were skipped and why), and the owner's daily summary of these metrics.

The channel ID read with youtube.readonly is only compared with the configured channel and shown to the owner; it is not stored by the Tool.

The project folder is under version control, and a copy of it is kept in the owner's own repository on GitHub. That copy is a backup for the owner; it is not shared with anyone.

5. How the data is used and shared

  • The upload journal is used to schedule the brand's videos, to make sure a video is not uploaded twice, and to know which videos to collect analytics for.
  • The analytics metrics are used by the owner to compare how the brand's own videos perform and to improve the next videos.
  • The data is not sold, not used for advertising, and not shared with or disclosed to any third party. No third party serves content or advertisements in the Tool or on this website.

6. Cookies and similar technology

The Tool runs on the owner's computer and does not store or read cookies or similar technology on anyone's device. This website uses no cookies, no scripts and no analytics or tracking. The website is hosted on GitHub Pages; as the host, GitHub processes the requests made to it under its own privacy statement.

7. How long data is kept

  • Sign-in token - kept while the owner uses the Tool. It stops working when access is revoked (section 8) or when Google expires it, and the owner can delete the file at any time; revoking access from the Tool itself deletes it (section 8).
  • Analytics metrics - YouTube Analytics data may be stored long-term under the YouTube API Services Developer Policies. The Tool asks for fresh data for each published video once a day, using the owner's authorization anew each time; the most recent days are re-read and replaced until YouTube's figures settle.
  • Upload journal - the data YouTube returned for an upload (video ID and link, scheduled publication time, privacy status) is refreshed from YouTube (videos.list) once it is 7 days old; a video YouTube no longer returns is marked as removed. A record whose YouTube data could not be refreshed for 28 days loses that data automatically; the owner's own part of the record (title, internal references) is kept.
  • When access ends - if Google refuses the authorization (the owner revoked access, or Google expired it) and access is not granted again, every YouTube step stops, and 25 days after the first refusal the Tool automatically deletes all data it obtained through YouTube API Services: the analytics metrics with their collection log and summaries, and the YouTube data in the upload journal. Granting access again before then cancels the deletion. The time of the refusal and of the deletion are kept in the status file next to the token.

8. How to revoke access and delete data

Access granted to the Tool can be revoked at any time on the Google security settings page: https://security.google.com/settings/security/permissions. After that the Tool can no longer upload videos or read any data through YouTube API Services until access is granted again, and the stored data is deleted as described in section 7. The owner can also delete the token file on the computer the Tool runs on.

Access can also be revoked from the Tool itself, with one command: the Tool asks Google to revoke its token, deletes the token file and at once deletes all data it obtained through YouTube API Services, for every channel (it first lists what it would do, and acts only when told to). If Google answers that the token is already invalid, the Tool still deletes the token file and the data. The time of the revocation and of the deletion are kept in the status file next to the token, and the deletion is logged.

The owner can delete the data the Tool obtained through YouTube API Services at any time, for all channels or for one, with one command of the Tool (it first lists what it would delete, and deletes only when told to). A request to delete this data sent to the contact address below is carried out within 7 days.

9. Changes to this policy

If the Tool starts to access, store or use data differently, this page is updated first and the effective date above changes.
